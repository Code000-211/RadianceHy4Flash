# M-13 (CWSR off on a dedicated box): CLOSED — worth ~68 MiB, and the engine will not serve under it

Item as written (backlog §3.8; derivation `audit/E-memory-placement-kv.md` E-R3): 2 compute queues x 35.36 MiB measured
(`queue_bytes`, mostly the context-save area with `cwsr_enable 1` in the hardware report); `amdgpu.cwsr_enable=0`
should drop that to ~1-2 MiB a queue, ~68 MiB = 48 units; loses mid-wave preemption; lossless numerically; S
(config + reboot); verify the "hardware queues" line. It is an operator setting, so no file in the tree has to change:
this note is the whole item.

## The number, and why it needs no code

- `queue_bytes` is measured at bring-up, not assumed: free, read `vram_free`, open a second compute stream, read again,
  the difference is one queue (core/engine_bringup.cpp:1850-1865). The budget charges `n_queues * queue_bytes +
  scratch` (core/mem/vram_budget.cpp:54-57) and prints `hardware queues   N a card at X each, measured`
  (vram_budget.cpp:326-334; the short-by form at :171). Two queues a rank (a third where a rank runs a second lane,
  engine_bringup.cpp:1862): 2 x 35.36 MiB = 70.7 MiB charged, of which the item keeps ~68 MiB once ~1.5 MiB a queue
  is left.
- Cross-check on the 35.36: KFD's context save area is `cwsr_size + ctl_stack_size`, 29.3 MiB on a 64-CU RDNA4 card
  (tests/place_test.cpp:4637), + the queue's ring and EOP/scratch; a fleet charges 41 MiB a kept queue, measured
  (`24 of them 0.99 GiB of a card, measured`, core/fleet/fleet.cpp:181-198).
- 68 MiB = 48 units = 0.23 points of residency, by the backlog's own arithmetic (§3 line 783: 100 MiB = 70 units =
  0.33 points, 20,992 units a rank), or ~4,886 tokens of context a rank (14,592 B a token, audit E:126).
- The saving arrives by itself: the item expects the same measurement to read ~1-2 MiB a queue with
  `cwsr_enable=0` (a lane must confirm it, step 3 below), so the receipt, the claimable figure and the KV and expert
  sizing follow with no edit. Read from the code here; no card in this run.

## Why it closes without code

- The engine refuses to serve under it: the diagnostic marks `cwsr-off` Incompatible wherever cards serve
  (core/diag/checks.cpp:238-249), `Engine::check_configuration` turns that into `radiance does not start on a
  configuration it does not support` and `RAD_E_UNSUPPORTED` (core/engine_diag.cpp:38-60), and bring-up warns with the
  fix (core/device/dispatch.cpp:71-90). Starting anyway takes `server.proceed-with-incompatible-configuration`
  (core/config.cpp:465, :1419), which turns every other guarantee off and prints the unsupported banner and
  `unsupported_configuration: true` (checks.cpp:417-424, docs/GUIDE.md:65). A lane A/B would then be measuring a
  configuration the project does not support, and the merge bar's "no e2e regression beyond noise" has no baseline to
  hold it against.
- And the hang is this configuration's own mode, not a corner. The guide's reset row states the mechanism
  (docs/GUIDE.md:4826): "the driver evicts a process's queues whenever host memory the card maps moves under memory
  pressure, and with `cwsr_enable=0` it cannot preempt a running queue, so the eviction waits on a queue that never
  drains". A serve maps a lot of host memory: the host pool of the example config is 8 GiB (GUIDE.md:925) and it is
  mapped into the card, not merely pinned (core/mem/pools.cpp:222-229, `RAD_MEM_HOST_MAPPED`, kernel-addressable),
  beside the host activation arenas and, with `engram in ram`, whole tables. Under 138 GB of weights on 32 GB cards the
  card is evicting by design. The failure is `MES failed to respond to msg=REMOVE_QUEUE` / `MODE1 reset`: the card
  resets, the engine aborts, and VRAM and the power cap, fan curve and voltage offsets go back to firmware defaults
  (GUIDE.md:4826); the stall watchdog names the queue (core/device/aql.cpp:1059-1076).
- It is not the largest of the three lossless memory levers on that box, and it is the only one that needs an
  unsupported serve: M-09 takes up to 112 units (a core/device item) and M-10 20-140 units plus 45, both inside the code
  with no unsupported flag. 48 units bought with a reset mode is not a trade the merge bar can take — and as a memory
  lever it has no kernel or op ms to show in the first place.
- Seen and left alone: the fleet's fixed `kQueueBytes = 41 MiB` (core/fleet/fleet.cpp:198) is measured with CWSR on, so
  a fleet's queue plan would not see the saving under CWSR off. It over-charges, so it stays correct; not touched here.

## The operator note itself, if the box owner still wants to measure it

On a dedicated box, as root:

```
echo 'options amdgpu cwsr_enable=0' >/etc/modprobe.d/amdgpu-cwsr.conf
mkinitcpio -P                    # or: update-initramfs -u -k all
reboot
cat /sys/module/amdgpu/parameters/cwsr_enable     # must print 0
```

What it costs: mid-wave preemption — no `rocgdb` on a running queue, no preemption between processes sharing a card,
and the eviction hang above. Numerically it is inert: CWSR saves and restores a wave's registers and is not in the
data path, so no bit changes and there is no KL to report.

What a lane would have to show before this item could reopen, in order, each step run through
`scripts/backlog/lane.sh <lane> <command>` (CARDS.md §1.1):

1. Baseline with CWSR on, the box as it serves (TP2, `/srv/models/hy4-flash-iqr-v4/`): the receipt's `hardware queues`
   line (expect `2 a card at 35.36 MiB each`), `claimable`, `elastic` and `vram_kv`, the `/stats` experts tiers'
   `units` (core/server/dashboard.cpp:489), and the startup report's host block, `amdgpu cwsr_enable`
   (core/diag/report.cpp:82).
2. Reboot with the parameter 0. The startup report's host block must read `amdgpu cwsr_enable 0`, `/diagnostics` must
   carry the `cwsr-off` finding as Incompatible, and a plain start must refuse; start with
   `--proceed-with-incompatible-configuration` and keep the banner in the log.
3. Re-read the same lines: `2 a card at ~2 MiB each`, ~68 MiB more `claimable` and `elastic` (its split between
   `experts` and `kv cache` as the config asks), ~48 more units placed. Much under 40 units makes the item a loss.
4. A/B the same e2e on the same build (the §2 c1/c8 stamps and the coupled DFly2 run), and watch `journalctl -k` for
   `REMOVE_QUEUE` / `MODE1 reset` across a soak long enough to force an eviction — an hour of serving with the prefix
   cache's host tier on and the 8 GiB host pools in place — re-applying the offsets after any reset. One reset ends
   the measurement and the item stays closed.
5. Record the lane and the receipt lines in the reopen note; the merge bar here is units, not ms.

Closed per the card's rule (number, then reason): 68 MiB = 48 units = 0.23 points, a memory lever with no ms, under a
configuration the engine refuses and whose failure mode is a full card reset.

Lane: none (no GPU).
