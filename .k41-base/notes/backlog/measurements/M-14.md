# M-14: how much of the card's held VRAM is device code

Instrument by andymail90-web (PR #184, `fc85abc`: `DeviceBackend::code_resident`, the receipt line `of which code`); fixes
and measurement on top of it by the reviewer. Machine: local lane (inference host), TP2, 2 x AMD Radeon AI PRO R9700
(gfx1201), power cap read back 210 W before the runs, `nospec.yaml`, model hy4-flash-iqr-v4-u3, libr4d/libavx built from
this tree. Runs `runs/local/m14r1`, `m14r2` (phases c1,c8; server.log kept on the lane host), each with the exit line.

## Findings

- At the plan (the receipt's "already held" line) the card has loaded **1 code module, 41.21 KiB**: modules load whole at
  their kernel's first launch, and the plan reads before any kernel but the bring-up's own has run. So the receipt line
  can only say "~0", and it is labelled so now ("when the plan read it; the exit line has the served figure").
- After serving (c1 + c8), **31.54 MiB in 27 code modules per card** (same on both cards, identical in both runs).
  `core/engine.cpp` now logs this at exit: `device code resident at exit: ...`.
- Against the item's quoted basis: libr4d carries 110.6 MB in 121 modules; a served run loads 27 of them, 31.54 MiB,
  i.e. 22 % of the modules and ~28 % of the bytes. The other 94 modules are never loaded and cost the card nothing.
- Against the card: 31.54 MiB is 0.10 % of 31.86 GiB, and 2.0 % of the 1.56 GiB `already held` (which is read before
  these modules load, so it does not contain them; they come out of the driver-drift / unclaimed margin).
- Counted per loaded executable (one `hsa_executable` per Module and card). A code object registered from two
  translation units loads only where its own stub is launched; if both launch, the card holds two copies, and the
  count says so, which is the VRAM truth, so it is not deduplicated.

## Decision

Trimming could give back at most the 31.54 MiB the served forms already need minus whatever a finer split of those 27
modules leaves out: tens of MiB was the item's own upper guess, the loaded share is 31.5 MiB in total, and part of it
is the code the model runs. Not worth a build/packaging change: see `closed/M-14.md`. The instrument stays, for
other builds and quantizations.
