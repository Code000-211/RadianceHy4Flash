# C-07 — closed: the pass is not empty, so dropping it buys nothing

The item (issue #95) targets DFly2's **empty** context pass, priced at two barrier rounds (~5–20 us a
step). The export was built, tested and approved; the lane run does not support merging it.

## The measurement (210 W, cold start, 3 interleaved rounds a side)

base `d13d29c8` vs head `3ec147cd`, house config, greedy parity 4/4 byte-identical in every round:

```
draft pass exclusive        base median     head median     delta
c1, us/pass                    3950.6          4034.4      +83.8  (+2.12 %)
c8, us/pass                    4990.1          5019.2      +29.1  (+0.58 %)
c1 agg tok/s                     90.1            95.5
c8 agg tok/s                    206.2           204.0
```

Kernel rows: the base's draft pass carries `mla_row_front` (42.6 us/pass) and two `add_rmsnorm`s
(8.5 + 6.9); the head has none of them and carries `r4dchain_kv_store` (36.7 us/pass) instead.

## Why it closes instead of merging

The premise fails on this config: the pass is not empty, so the drop relocates work rather than removing
it — 58.0 us out, 36.7 us in, and the pass is 0.58 % slower at c8. The call site declares the export
unconditionally (`arch/hyv4flash/hyv4flash_dfly.h:962`), where the item's own pointer is
`draft_pass < 0` (`hyv4flash.cpp:1113-1119`).

Under CARDS.md §2 the second clause is not met, so the code is withdrawn from the PR and this note is
the record.

## Reopen

- A block drafter that genuinely keeps no cache declares it, and the rows above are re-measured; or
- the call is gated on `draft_pass < 0` and the same three-round run shows the draft pass faster.

The gate itself is sound and stays tested in this branch's history (`0a810d6a`, `3ec147cd`); nothing
else in the item changes.
