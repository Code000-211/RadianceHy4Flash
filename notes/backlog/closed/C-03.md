# C-03 — the rank barrier: closed on the measurement, code withdrawn

The item (issue #98) asks for a spin-then-park rank barrier and, separately, pinning the step and rank
threads to one CCX. Both halves were built; both are withdrawn, and this is the record CARDS.md §2 asks
for when the bar is not met.

## The measurement

The accepted run is on issue #98 (`@0xb3-err`, 210 W, 3 interleaved rounds each side, container
`radiance-build:latest`, base `cf11ed50` -> head `397846a5`, greedy parity byte-identical on all eight
prompts). The targeted `ranks` row:

```
c1 `ranks` ms/step (per boot): before 3.34, 3.49, 3.36 (median 3.36) | after 3.36, 3.38, 3.38 (median 3.38)
c8 `ranks` ms/step (per boot): before 7.26, 7.64, 9.46 (median 7.64) | after 9.05, 7.99, 10.82 (median 9.05)
nsv `ranks` at c1:             before 0.58, 0.58, 0.58 | after 0.58, 0.58, 0.58
```

The item's term is **not faster**: c1 moves +0.6 % (3.36 -> 3.38 ms) and c8 moves +18 % *worse*
(7.64 -> 9.05 ms), though the c8 ranges overlap (before runs up to 9.46, after from 7.99). Served
aggregates are at parity: c1 126.76 -> 126.20 tok/s, c8 260.91 -> 264.56 tok/s, nsv c1 73.92 -> 73.80,
nsv c8 256.74 -> 256.28. Under CARDS.md §2 the second clause — "the kernel, op or step the item targets
is measurably faster in ms" — is not met, so the card closes and the code does not merge.

## Why the code goes too

The barrier is correct (generation counter, reset ordering, abort releasing a parked rank, a last
arrival that does not park), and its tests pass; but it buys nothing the measurement can see, so
keeping it would be an unmeasured change on the serving path. The pinning half measured −14.9 % tok/s
as an opt-in arm, was never compiled (no CMake entry), had a header describing a rule the code did not
implement, and had no test; it is dropped with its own record in
`notes/backlog/closed/C-03-pinning.md`.

## What is recorded here

- `notes/backlog/measurements/C-03.md` — the accepted run and its rows.
- `notes/backlog/closed/C-03-pinning.md` — the pinning half's drop, with its pilot numbers.
- The barrier's code and tests stay in this branch's history (`415d3793`, `5982d82e`) for anyone who
  wants to re-open it; the tree at this head is the merge base's, apart from the notes.

## Reopen condition

A barrier that moves the `ranks` row at c1 or c8 outside the noise above (three interleaved runs a
side, the same box and cap) re-opens the item; a pinner that does the same re-opens its half.
