# S-11 (issue #304): the runahead overlap, measured on the u3 lane

Record for the design card [`notes/backlog/design/S-11.md`](../design/S-11.md), which is simulation
only: it changes no code, so this file is not an A/B of a change but the measurement the note's
verdict and gate are built on - the decode step times, the miss rates and the trace the overlap is
computed over.

**who measured:** the Radiance-Builder agent of Moebius run-2733, on the lane below.
**before:** `4744d9297f0171f8c11a6db51e472778650f711c` (merge base of the card).
**after:** `9c24f73e` (the design commit: `notes/` only, no code). The tree that was built and run is
byte for byte the same for both ids, which is the point: these are the baseline numbers, not an
effect of the card.

**machine:** `iks`, 2 x AMD Radeon AI PRO R9700 (`gfx1201`, 32 GB each), TP2 (cards 0,1 through
`~/moebius-gpu/bin/gpu2`), power cap **210 W** a card (`/sys/class/drm/card*/device/hwmon/*/power1_cap`
= 210000000 on all four), 48 cores, kernel `7.0.14-30-pve`.
**ROCm:** runtime and host compiler from the ROCm SDK `7.14.0a20260612` (AMD clang 23.0.0git, patched
52226beb/PATCHED:440716f8); HIP device code from ROCm 10.1's AMD clang 24.0.0git (`d6f6cb69`) over the
VOPD-repeatable libLLVM, `-DRAD_HIP_VOPD_REPEATABLE=ON`, `-DRAD_GPU_TARGETS=gfx1201` - CARDS.md §1.1,
configured by `~/moebius-gpu/configure.sh`.
**container:** `hy4-flash-iqr-v4-u3.rad` (u3), `expert_tiered`, host pool 39000 MiB.
**ngram-placement:** `ram` (`placement: n-gram table in pinned memory the cards read, ... in shared
file /dev/shm/radiance-ngram/ngram-*.tab`), from `scripts/backlog/nospec.yaml`.
**lane:** `RAD_LANE=iks-A`, port 8042, `scripts/backlog/run.sh` over `scripts/backlog/nospec.yaml`
(no drafter) and `scripts/backlog/coupled03.yaml` (DFly2), model at `$RAD_MODELS/hy4-flash-iqr-v4/`
read only.

Seven runs, one after another in one lane, in this order (the arms interleave the two containers and
the W2 switch-off):

```
scripts/backlog/run.sh s11-nospec-a nospec.yaml c2,c4,c8
scripts/backlog/run.sh s11-nospec-b nospec.yaml c2,c4,c8
scripts/backlog/run.sh s11-nospec-tr nospec.yaml c4,c8 RADIANCE_AQL_STAMP=1 RADIANCE_ROUTE_TRACE=$PWD/runs/iks-A/s11-nospec-tr/trace.rt

scripts/backlog/run.sh s11-df-b coupled03.yaml c2,c4,c8
scripts/backlog/run.sh s11-df-nw2 coupled03.yaml c8 RADIANCE_W2=0
scripts/backlog/run.sh s11-df-tr coupled03.yaml c4,c8 RADIANCE_AQL_STAMP=1 RADIANCE_ROUTE_TRACE=$PWD/runs/iks-A/s11-df-tr/trace.rt
```

Each pair (a, b) is the interleave; `-nw2` is the single W2-off arm, used only to cross-check
[W2-prototype.md](W2-prototype.md) §5's 3.8 ms a step (25-28 us a miss here), not as a merge
measurement of its own.

**output parity:** none to report - the card runs nothing differently. The step time is the probe's
decode window, `1000 * (all_decoding_s[1] - all_decoding_s[0]) / decode_steps`, not `wall` (which
holds the prefill and a slow c8 start in `s11-nospec-a`: TTFT 4.87 s), and `ms_step` is null for a
multi-client phase, so the window is the only reading.

- nospec means c2 14.878 / c4 17.777 / c8 23.865 ms: `T(n) = 12.20 + 1.50 n`, so the fork is

- DFly2 means c2 22.879 / c4 30.143 / c8 35.413 ms (a step is two passes, draft and verify): the
  fork is c8 28.85 (a) / 20.90 (b) and c4 14.03 (a) / 17.20 (b); the fit over the three means gives a

- run-to-run spread (the noise floor the gate in §7 uses): nospec c2 0.92, c4 0.45, c8 0.85 ms (3.5 %

- W2 switch-off at DFly2 c8: 39.116 ms against 35.655 / 35.171 ms, over 140.8 misses a step (against
  103.9 with W2 on) - **3.5-4.0 ms a step, 25-28 us a miss**, W2-prototype.md §5 re-measured on this
  machine. So the stall a schedule could hide at c8 DFly2 is 3.5-4.0 ms, measured by taking W2 away.

## 3. The overlap simulation, and its raw output

The traced runs above hold the routing: `s11-nospec-tr` (c4 and c8 phases, 255 steps each) and
`s11-df-tr` (c4 and c8, pooled over the multi-client passes - 167 of them - because a DFly2 verify
pass's height moves with the draft length, so no single height selects the phase, and `--min-rows 8`
drops the single-client passes of the staggered start). Trace format `RADRTRC1`
(`core/place/rtrace.h`): per dispatch and layer, the pass's per-expert routing counts - which sum to
rows x 16, the sums say so - and every 256 dispatches a tier snapshot, the byte count and the movable
flag of the 42 x 512 units.

Tool: [`notes/backlog/design/S-11-tools/runahead.py`](../design/S-11-tools/runahead.py). The fork is
`2 * T(half) - T(merged)` from §1's step times, never modelled; a miss costs 66 us (the link: a unit
is 1,499,904 B, 891,136 gate_up + 608,768 down) or 34 us (the stall, what a pass pays for an in-place
read once the tail overlaps it). The halves are the hypergeometric expectation over a random half of
the rows, since the trace holds no row-to-token map.

## 4. What this record does not measure

- **u4.** No `u4` container exists on `iks` or on the two-card machine, and the item's 32-36 ms/step
  figure cannot be reproduced here. The note's §7 turns this record's numbers into the threshold a u4
  lane has to pass (177 misses a step at nospec c8 on the link bound, 344 on the stall bound; 317-438
  and 615-850 at DFly2 c8), and no card is opened from a projection.
- **A card's own parity.** Nothing runs differently, so there is no output to compare. A build card
  must show byte identity (or the band check the note's §8 asks for).
- **The halves are an expectation**, not a split that was run (see §8 of the note); the DFly2 step's
  fork term covers both of its passes, the conservative reading.
- **The W2-off arm is one run**, so its 3.5-4.0 ms is a cross-check of W2's own record and not a merge
  measurement.
