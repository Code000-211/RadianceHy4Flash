# C-03 — the rank barrier on the decode step

- **before** `cf11ed50` (merge base), **after** `415d3793` (the code commit measured; this file's commit
  sits on top of it and changes nothing else)
- **measured by** krisf, locally, 2026-11-25
- **GPUs** 2× AMD Radeon AI PRO R9700 (`gfx1201`, device `0x7551`), TP=2, peer-to-peer direct memory
- **power cap** 300 W per card (`power1_cap=300000000`, read at pre-flight; the sysfs read returns
  `Device or resource busy` while the engine holds the card, so it was not re-read per round) — −50 mV
  curve untouched
- **ROCm** `/opt/rocm/.info` reports `unknown`; `amd-smi` 26.2.1, HIP 7.1.52801
- **container** none (host process) — **ngram-placement** `disk`
- model `qwen3.8-27b`, config `hy4-u4-tp2-disk.yaml`

## Method

Interleaved: every round booted every arm (`base`, `c07`, `c03`, `c03p`) on the same machine with the same
settings, then ran one discarded warm-up decode pass, `c1` (decode), `pf20` (20.5 k-token prefill) and a
`greedy` parity phase. Four rounds.

`c03p` is the same binary as `c03` with the opt-in CCD pinning switched on, so the rank barrier and the
pinning can be told apart.

**Round 3 is excluded.** In it `base` fell to 33.2 tok/s while every other round put it at 100–106, and
`base`'s own greedy text drifted in the same run. The outlier is on the baseline arm, which no patch can
explain, so it is environmental rather than an arm effect; its cause was not instrumented (the probe's
warm-up still ran, and nothing in the run log records what else the host was doing). The rows below are
the three clean rounds (1, 2, 4) with round 3 kept in the raw lines for completeness.

The warm-up matters: without it the first request of every boot pays the expert page-in, and the same
prompt lands at either ~4.5 s or ~8.8 s of prefill (and greedy text differs run to run). With it the
numbers are tight and the parity check is stable.

The 1156-dispatch decode pass carries the change: wall **29.617 → 26.053 ms (−12.0 %)** at the same
dispatch count (1148) and the same busy time (19.839 → 19.933 ms), so the whole 3.564 ms comes out of
idle — **9.416 ms (31.6 %) → 7.296 ms (27.6 %)** — and the ordered gap p50 eases 4.08 → 3.90 µs. The
298-dispatch pass (prefill) is unchanged (4.701 → 4.737 ms), which is what the item claims.

Pinning (`c03p`) takes the same pass slightly further (25.983 ms, 24.8 % idle) but costs end-to-end
decode: 89.4 tok/s against 108.5 for `c03`. Its two clean runs (89.4, 93.3) sit far outside `c03`'s
(106.3, 108.5, 113.1). **Pinning should stay off**, which is its default.

## Output parity (§2.1)

`greedy` text sha256 (first 8 chars), same prompts in every run:

```
base r1/r2/r4 : 1f74c498, 960450a6, db3c7d07, 49354a13   (r4 identical)
c03  r1/r2/r4 : 1f74c498, 960450a6, db3c7d07, 49354a13
c03p r1/r2/r4 : 1f74c498, 960450a6, db3c7d07, 49354a13
```

Both arms matched the baseline on all four prompts in every clean round. The only divergence seen in the
whole window was `base` against itself in the excluded round 3 (`1f02baf6, d54a3480, db3c7d07, 33def547`),
i.e. the baseline is not bit-stable when the host is contended — which is why round 3 is out.

## Verdict

Measured win. The rank barrier removes 3.6 ms of a 29.6 ms decode pass — all of it idle — and 2.1 points
of idle share, with output parity intact and prefill untouched. Served decode throughput rises 3.3 % on
this rig; the stamps say the mechanism is real even where the served number is close to the run spread.
