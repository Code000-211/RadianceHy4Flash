# C-03 — the measurement, and what it says

Container lane, 210 W per card, three interleaved rounds a side, base `cf11ed50` -> head `397846a5`,
`radiance-build:latest` (ROCm 10.1.0 in the image), greedy parity byte-identical on all eight prompts.
Posted on issue #98 by `@0xb3-err`; the rows below are theirs, quoted, not re-measured here.

## The item's term: `ranks` ms/step

```
c1, per boot:    before 3.34, 3.49, 3.36  (median 3.36)
                 after  3.36, 3.38, 3.38  (median 3.38)      +0.6 %
c8, per boot:    before 7.26, 7.64, 9.46  (median 7.64)
                 after  9.05, 7.99, 10.82 (median 9.05)      +18 %
nsv, c1:         before 0.58, 0.58, 0.58  | after 0.58, 0.58, 0.58
```

The c8 medians separate, but the ranges overlap (before reaches 9.46, after starts at 7.99): on this
box the c8 `ranks` row is not stable enough to call a regression, and it is certainly not the gain the
item asked for. c1 is flat.

## Verdict

CARDS.md §2's second clause is not met: the `ranks` row the item targets is not measurably faster. The
card closes with `notes/backlog/closed/C-03.md`, and the barrier code is withdrawn from this PR rather
than merged unmeasured. Nothing in this run supports shipping it for a different reason, and the pinning
half was already dropped on its own pilot (`notes/backlog/closed/C-03-pinning.md`).

Caveats, as posted with the run: numbers from this box compare only with each other; the ported harness
lived in the lane, not in this tree, and has been removed from this PR.
