# P-06 Engram: one CONV history for the four Engram layers -- measurement

- **before** `34862f3d` (default branch the PR was merged with: merge base of the measured tree)
- **after** `60a535d3` (code commit: PR head `3dda6773` merged with `34862f3d`; the commit that adds this file changes nothing else)
- measured by the PR-processing agent for the repository owner, on iks, lane `iks-A` (TP2, cards the scheduler gave `gpu2`),
  both arms on the same lane, interleaved base / code round by round
- GPUs: Radeon AI PRO R9700 (`gfx1201`), TP2; power cap read back before every run: 210 W on all eight cards of iks (the `cap` lines of each run)
- ROCm: the SDK wheel of `~/moebius-gpu/configure.sh` (clang from `_rocm_sdk_devel`), build `RAD_GPU_TARGETS=gfx1201`, trees `RadianceHy4Flash-pr262-base-a` / `-pr262-a`
- container: `hy4-flash-iqr-v4-u3.rad`; `ngram-placement: ram=/dev/shm/radiance-ngram`, host pool 16000 MiB (lane `iks-A` as in CARDS.md 1)
- configs: `nospec.yaml` (3 rounds) and `coupled03.yaml` (2 rounds: round 3 was lost when iks went down, both arms)
- note: what the PR does is the "one state" variant (audit F20): one `engram_ids` a layer stays (4), the three extra `engram_state` launches and the three extra CONV rows are gone

## Result

| row | before | after |
|---|---|---|
| `engram_state_kernel` launches / step (stamps, c1, 3 runs) | 4.0 x 2.3 us = 9 us | 1.0 x 2.3 us = 2 us (-6.9 us) |
| `engram_ids_kernel` (4 launches / step) | 4.1 / 4.1 / 3.9 us each | 4.9 / 4.9 / 4.9 us each (+0.8 us each, +3.2 us: the `advance` parameter read) |
| ids + state per step | 25.6 us | 21.9 us (-3.7 us) |
| engram group, `agg.py --match 'engram\|conv'` | 16 launches, 118.4 / 116.7 / 116.8 us | 13 launches, 113.7 / 113.2 / 113.2 us (-3.5 us, -3 launches) |
| nospec `c1` agg tok/s | 75.9 / 75.8 / 76.1 | 75.8 / 76.0 / 76.2 |
| nospec `c8` agg tok/s | 322.6 / 325.4 / 322.7 | 323.5 / 323.4 / 324.7 |
| coupled03 `c1` agg tok/s | 150.8 / 151.0 | 150.9 / 150.5 |
| coupled03 `c8` agg tok/s | 404.4 / 394.0 | 405.0 / 392.2 |
| greedy (3 prompts + 5.7K arrival), nospec and coupled03 | sha256 identical | sha256 identical to before, byte for byte |

The saving is 3.5 us of 13.3 ms a step (0.03 %): end to end it is inside noise (c1 +0.1 tok/s, c8 +0.6 tok/s on medians), as the triage said (<= 0.3 %). The 3 fewer CONV rows
per checkpoint / rollback are not on these rows. The ops the item removes are measurably cheaper (-6.9 us of `engram_state`), `engram_ids` pays 0.8 us a launch for the extra parameter.

Greedy sha256 prefixes: nospec `d6da4fb33e 0699709c4b e7a23c5d9a 466e53a292`; coupled03 `5b7a3975de f55fe02071 0075e702df 717c3b789e`, all runs of both arms.
