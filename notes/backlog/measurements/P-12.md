# P-12 measurement: the 64-/128-row levels, measured and closed without code

Status: **measured**, then closed without merging. The full record, including the patch that was tried and why it
cannot be made safe from today's core, is `notes/backlog/closed/P-12.md` in this same diff. This file is the
measurement CARDS.md §6 asks for, at the path it names.

## What ran

Two arms on one tree, one lane, one boot an arm, three interleaved runs each: the stock 256-row floor against a
scratch build with the floor at 64 rows and the level progression `R = (R < 256 ? R * 2 : R * 4)`. Both arms read
their lend table off the boot line (`I activation arena: lends …`).

## The numbers

| | 64-row floor | 256-row floor | delta |
|---|---|---|---|
| level size at 64 rows | 91.26 MiB | 257.57 MiB | −64.6 % |
| lends at ≤64 tokens | 2.60 GiB | 2.44 GiB | +0.16 GiB |
| lends at ≤1024 tokens | 1.79 GiB | 1.79 GiB | — |
| `c1` decode tok/s, median of 3 | 129.42 (98.33 / 129.42 / 146.01) | 130.48 (132.38 / 130.48 / 124.89) | −0.8 % |
| `c8` decode tok/s, median of 3 | 276.35 (276.35 / 256.91 / 281.12) | 272.15 (272.15 / 259.05 / 286.59) | +1.5 % |
| `c8` aggregate tok/s, median of 3 | 238.97 | 241.20 | −0.9 % |

Output parity holds: the same greedy completion on both arms is byte-identical (`md5 67b91aaa3d0c198307a015305eba0402`).

## Why it is closed rather than merged

The measured part is the amount of memory the level *reserves*, not a speed gain — every end-to-end figure is inside
the noise of its own arm. The part that would make the smaller levels safe (rounding every transient's rows up to the
write tile of any kernel that writes it) has nowhere to live: `RadBufDecl` and `BufferInfo` carry no write-tile
metadata, so the core cannot express the constraint the shortcut needs. Closing at −0.8 % / +1.5 % rather than
changing the buffer ABI.

Reopens when the ABI can carry write-tile metadata; the patch is preserved on the scratch branch named in
`closed/P-12.md`.
