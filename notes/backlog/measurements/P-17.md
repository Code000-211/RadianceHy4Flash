- **after** `44c0361e` (the code commit; this note is the only commit on top of it)
- GPUs: 4 × AMD Radeon AI PRO R9700 (gfx1201), TP4, one machine
- Power cap: 270 W on every card (read before each run, in the `==` lines)
- ROCm: core 10.1; kernel 7.0.0-44
- Container: `hy4-flash-iqr-v4-u4.rad` (keptn/hy4-flash-iqr-v4, u4), `ngram-placement: ram`

- Arms: **A** = before; **B** = after with `RADIANCE_HY4_PIPE_ATTN=1` (the split); **C** = after with the
  switch off (the default). Order A1 C1 B1 B2 C2 A2 A3 C3 B3, one script under one `flock`, a fresh

  throughout; the switch's corrected count rises slowly (725 → 765 over the round), as on every run on
  this machine.

## Sizing on the before tree (the brief's step 1)

Order P1 A1 L1 O1 O2 L2 A2 P2 P3 A3 L3 O3, same config and probe (no c1). Labels here: **P** = pipe on
(today's default prefill with `RADIANCE_HY4_PIPE=1`), **A** = pipe on with the absorbed prefill
(`RADIANCE_HY4_PREFILL=absorbed`), **L** = `RADIANCE_HY4_PIPE_LANE=0` (pieces on one lane), **O** = pipe off.

| Arm | prefill tok/s mean (sd) | vs P |
|---|---|---|
| P pipe on | 5338.0 (34.8) | — |
| A pipe on, absorbed | 5186.6 (41.9) | −2.8% |
| L one lane | 4733.6 (28.5) | −11.3% |
| O pipe off | 4888.7 (6.0) | −8.4% |

The absorbed form costs about 2.8%. The split does not need it: the dense (sliding) layers' kernel puts
query i at key n − m + i, so piece 1 runs over all the step's keys without the absorbed form. An earlier
round (pre-final code, A/B/C/D, D = split with the absorbed prefill) had D −0.57% vs A and different
hashes from A (logprobs differ from token 0, greedy tokens agree to 37/14/49/37 of 64), which is the
absorbed form's known difference, not the split's.

## Layout note

The first round's switch-off arm was −0.83% vs before. The cause was an extra persistent plane for the
piece bounds, which shifted the fixed arena region from 232.25 to 232.50 KiB. The bounds now live in 8
extra i32 at the tail of `cu_prefill`, declared only when the switch is on; C is then −0.08% (inside
noise), and B rose from +2.20% to +3.27%.

## Merge-bar verdicts (CARDS.md §2)

1. **Output:** byte-identical. Same four hashes (ids plus logprobs) in every run of A, B and C.
2. **Targeted step faster:** yes. The pipelined prefill step (TTFT of a single prefill) is 3.1-3.3% shorter per
   prompt with the split on, and prefill tok/s is +3.27%, with every B sample above every A sample. No
   profile-ops or AQL stamps were taken; the step is the whole prefill.
3. **e2e not worse:** c1 decode 120.86 / 120.88 vs 120.94 tok/s (−0.07%, inside noise; decode never takes the
   split). With the switch off, prefill is −0.08% (noise).
