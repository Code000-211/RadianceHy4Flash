## 1. The item's shape: M 2048 x F 1536 x K 1536, top_k 16, 128 experts, three-bit, limit 10

32768 routed rows: the model's prefill at 2048 tokens a rank.

```
run 1  the pair 3644.0 us (gemm 3172.6 + quantise 471.4), the fused row 3948.2 us, +8.3 %
run 2  the pair 3652.4 us (gemm 3189.3 + quantise 463.1), the fused row 3946.7 us, +8.1 %
run 3  the pair 3671.0 us (gemm 3197.8 + quantise 473.2), the fused row 3942.0 us, +7.4 %
```

The fused row costs about 274 to 298 us a layer more than the pair it replaces, where the item
expected the quantiser's 41 x 254 us (10.4 ms, 1.8 % of a chunk) to go away. Per layer its epilogue
costs about 770 us against the quantiser's 474 us: the fused kernel's GEMM is the packed GEMM's time,
and the swiglu, the staged group, the rotation and the code stores are what it adds.

(third of the three runs; runs 1 and 2 read the same within a few tenths, and the split and dot rows
are the only ones where the fused row is ahead: -4.2 / -5.1 / -5.8 % and -15.5 / +3.3 / +5.0 %.)

Decode-height steps are 9 to 10 % slower, which is why the fused row is declared outside
`r4d_moe_decode_band`'s heights and the pair keeps those steps. One flake: run 1's first four-class
line read 39.2 us against the pair's 30.1 us (+30.3 %, and the pair's quantise read 5.9 us there where
every later line reads 4.1) and failed the selftest's "not slower than a fifth" timing bound; runs 2
and 3 read 31.4 against 28.5 and 31.3 against 28.6. A 28 us op whose first launch pays the cold read
is at the edge of what that bound can hold; it is the one red line of the three runs.

One defect this note has to carry: the four-class branch issued its fused form with **10 operands**
where its row reads up to index 14 -- `[12]` the codes, `[13]` the scales, `[14]` the step's split --
because its count is written `9 + ...` over an array that has thirteen leading operands before those
three (`rad_block_moe_fp8.h`, `pass()`, the `ncls == 4` branch). The two-class form, the one the served
model takes, has the right count (10 without a split, 11 with). What the runtime did with the short
list cannot be read off these rows: the four-class cases compare against the pair either way, so a
fallback to the pair passes as well, and their steady ~10 % gap over "the pair" line reads like the
two-class fused row's gap, not like a second run of the pair. Either way it is a real defect in the
four-class branch, and one more reason this shape is not worth fixing forward: the served model never
takes that branch.

## 3. Where the epilogue's time goes (ablations, timings only)

Two builds whose results were **not** checked, to bound the parts of the 770 us (`M=2048` row, same
card, one run each):

```
rotation + quantise replaced by a copy of the staged row:  the pair 3645.5 us, the fused row 3782.4 us, +3.8 %
the gate tile's shared-group round trip dropped:          the pair 3638.5 us, the fused row 3720.1 us, +2.2 %
```

So the rotation and quantise are about 170 us, the gate tile's round trip about 60 us, and the swiglu,
the group's staging and the code stores the rest (about 550 us) -- against the 474 us a standalone
quantiser takes for the same 32768 rows with the whole grid at its disposal. The epilogue is
latency-bound, not throughput-bound: the fused block does all of that for the 128 rows it holds, one
128-column group at a time, and the only shape that could hide its latency (more rows a block) is the
one the packed map's eight-token-tile walk fixes. `#pragma unroll 2` on the rotation loop changed nothing
(3948 us with it, 3938 us without, within run-to-run noise).

## 4. What the merge bar also asks for, and is missing

- **kbench prefill rows on the served checkpoint**: the fused row cannot lay out Hy4-flash's gate_up
  table (`moe_gemm_iqr_gated cannot lay out the table 'w' from trellis:codes=u3[1x1] ...: container
  format error`, `tools/rad_kbench.cpp:3134`), so all 56 of its kbench cases are skipped and the
  served model falls back to the pair. No served row exists for it.
- **a served prefill / decode A/B with output parity**: none. There is one machine with two cards and
  no lane, and with the fused row unresolved on the served checkpoint an e2e A/B would compare the
  pair with itself.

## 5. Why the change's first numbers were a win and these are not

This note's first revision measured the change at `fb2262af` **on `iks`** (4 cards, ROCm 7.14.0),
against the merge base of that day, `cf11ed50`: the pair took the run map at four token tiles,
4524.0 us at this shape (GEMM 4006.1 + quantise 517.8), and the fused row on that same map 4347.8 us,
-3.9 %. The base has since given `moe_gemm_iqr` the three-bit packed map (another card's change, index
8 of `moe_gemm_q`'s operands being a quantised plane, `kPackTiles = 8`,
`kPackMinRowsPerExpert = 32`): this machine reads 3168 us of GEMM at the same shape, where iks's 4006
was the run map at four token tiles -- eight token tiles a block decode a weight unit once for twice
the rows, a fifth of the op, where the quantiser is a ninth of it. The fused row must walk its pair's
map to stay byte-identical (that is what makes the split step match), so it cannot keep the cheaper
form, and on that map its epilogue costs 770 us where the pair's quantiser costs 474. Its best form is
therefore 8 % behind here, not 4 % ahead there.
