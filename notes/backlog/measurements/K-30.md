## What is on the served path

On Hy4-flash only `sample_topk` (and `sample_logprobs`, when a request asks for logprobs) is reached
(`core/sample/sampler.cpp`); nothing declares `sample_chain`, so its top_p fix is a correctness fix with **no Hy4
speed or output effect**. The measured part is the shared `radix_select`: one counting histogram a block before,
eight (one per four waves) summed after.

The sampler's kernels are in neither the AQL stamps (a stamped `c1,c8,greedy` run of the after tree: 3.7 M records, no `topk` / `sample`
kernel among them) nor the `profile-ops` table (`prof.yaml c1s,c8s` on the before tree: no `sample_*` row), so the kernel row is
`rad-kbench`'s.

## Verdict against §2

1. Byte-identical: greedy and seeded sampled output identical in all runs of both arms; kbench against libref exact.
2. The targeted kernel is faster: `sample_topk` 74.5 -> 67.0 us (-10 %), `sample_logprobs` 80.4 -> 73.1 us (-9 %),
   every after session below every before session.
3. End to end not worse beyond noise (c1 -0.07 %, c8 -0.33 %, overlapping ranges; the kernel gain is 0.06 % of a
   step and not resolvable end to end).

The `sample_chain` top_p fix (q62 mass, and the top_p passes' own `prefix_p` word) has no Hy4 effect: it is a
determinism fix for the architectures that use the fused sampler, covered by the emulator tests in both thread
orders and by the card selftest row.
