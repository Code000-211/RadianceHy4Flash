of the item; part (b), the study on AVX-512 hosts, is M-19b in the backlog and not in this change.

This is the second measurement of the pull request. The first (head `ffedf6b6`, code `0b7af54a`) had two rows worse
beyond noise; the review asked for changes. Where those rows stand at this head, **what does not hold cleanly first**:

- **Decode right behind a newly staged prompt.** The decode rate over the tokens after the first one is still lower,
  outside the run spread: behind a lone 723-token prompt by 1.1 % over 64 tokens and 0.2 % over 256 (was 2.4 % over
  64), behind the 6.7K-token prompt by 2.1 % over 64 tokens and 0.4 % over 256. The last of those tokens arrives
  sooner in every run: by 37 ms behind the lone prompt, by 113-122 ms behind the 6.7K one (§3). The first token
  comes 43-46 and 128-143 ms earlier, into the same seconds for which the expert slab's arena loan is back; a
  rate counted from the first token reads lower for that.
- **The resume conversation's own prefill** (7,405 tokens, staged the same in both arms) reads 18 ms slower in one
  order, outside the spread, and 3 ms in the other, inside it; over the six runs 1.891 -> 1.902 s, inside the before
  runs' range (§1).
- **The resumed turns** (252-379 rows, staged in neither arm) were 6-11 ms slower. They are level now: +0, +1 ms,
  -1, -1 ms and -3, +2 ms in the two orders, inside the before runs' range (§1, §4).

Everything else the Verify line names holds: the texts are byte-identical, `pf6` is 145-148 ms faster, the 720-row
step's routed GEMMs are 3.5x cheaper, and a 256-row prompt does not move.
