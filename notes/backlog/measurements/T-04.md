# T-04 measurement: `rad-kbench` cases at the Hy4 TP2 shapes that were missing (#111)

Measured per CARDS.md §6 step 3, against the merge bar in §2. No kernel, op or step changes here: the
item adds recording cases to `data/kernels_hy4.rkb` and one rule in how a case's table of pages is
drawn, so its bar is parity -- the recording still agrees with the reference, card-less and on a card
-- plus what the new rows cost the sweep. It is not a speed claim, and none of the numbers below is
one.

## The two commits

- **Before:** `ac66d3a0`, the merge base this branch starts from. `data/kernels_hy4.rkb` holds 1003
  cases and none of them is at the four shapes D-10 names: no `mla_attn_paged_sink` at 32 heads and
  window 512, no `mla_attn_sel_sink` at 16 heads, no trunk row above M 8, and `gemm_nt_q` only to
  M 512.
- **After:** `80061e5c`, this branch's tip: the recipe, the cases and their test, on top of
  `6eaef381` (the block-order timing inputs). The
  fixture holds 1301 cases: the 1003 of the merge base byte for byte, then 298 recorded ones. The
  base's cases were appended, not rewritten -- `base prefix identical: True`, and the added 298 are
  `identical to the recording: True`.

## Who measured, where

- **Measured by:** the change's author, in Moebius run 2804; this file is that measurement.
- **GPUs:** `iks`, 4 x Radeon AI PRO R9700, `gfx1201`, 32 GB each. Every run held exactly one card
  (that machine's `gpu1`), one run after another.
- **Tensor parallel:** the cases are one rank's. TP2 splits Hy4's 64 query heads over two ranks, so
  the sliding attention case is at 32 heads (K-14's `merge_sink` shape) and the selected attention
  case at 16, over TP1's latent / rope / block geometry.
- **Power cap:** 210 W a card (`rocm-smi --showmaxpower`, all four).
- **ROCm / driver:** ROCm 7.14 (TheRock nightly, the `gfx120X-all` wheel set under `$HOME/.local`),
  host toolchain through a sysroot, `RAD_HIP_VOPD_REPEATABLE=ON`; `rocm-smi --showdriverversion`
  reports `7.0.14-30-pve`.
- **Container:** none -- the host's own tree, the same configure line on both sides.
- **ngram-placement:** not involved. No model, no engine and no server is started by any run here:
  `rad-kbench` loads the kernel libraries and replays the fixture.

Per op: `mla_attn_paged_sink` 84 -> 126, `mla_attn_sel_sink` 14 -> 24, `gemm_nt_q` 56 -> 74; the rest
are the trunk rows' heights. The expert planes (K 13824 / 16384) are deliberately out: the card-less
gate replays every case on every run, and 150 GFLOP of reference per case would have cost it about
twice what the whole recording costs.

The `sel` cases carry real `qsa_select` tables: a row's pages are drawn in block order (the timing
input law of `6eaef381`), which is what a real `qsa_select` hands a row -- ascending runs of the blocks
it selected -- rather than one shuffled permutation for the whole operand.

its own.

### The encodings the first recording dropped, and how the card found it

The first cut of the 298 cases replayed clean card-less (3465 checked, 3465 passed, 0 failed) and fell
over on the card: 2540 checked, 2522 passed, 21 failed, worst rel_l2 1.700e+00.

- 18 were the `gemm_nt_q` i8a8h heights: the merge base's own `gemm_nt_q` cases replay 112 of 112
  clean at 1.032e-04; the branch's 148 checked / 130 passed / 18 failed at 1.700e+00.
- 3 were `logits_gemm` bf16 at M 24 / 40 / 48, refused by `logits_gemm_i8` as "a dtype this kernel
  does not serve".

The cause was the recipe, not a kernel: `m_clone` copied a recorded case to another M through `fresh`,
which drops a case's operands to plain weights -- right for `heads_clone` and `wide_clone`, which
resize the weight itself, wrong for a clone that resizes only the M tall rows. The container's 8-bit
codes and their scales went with it, so a quantised row was handed plain weights, and the plain weight
then matched the geometry of a row that serves the encoded form. `fresh` now takes `keep_encodings`,
`m_clone` passes it, `tests/kbench_recipe_test.py` holds both rules, and the 298 cases were re-recorded
on the card: 298 cases, 0 dropped, keys unchanged, 192 of them carrying an encoding. On the card the
fixed recording replays 2543 checked / 2543 passed / 0 failed at 3.183e-03.
