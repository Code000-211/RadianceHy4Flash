## Method

`RADIANCE_AQL_STAMP=1 scripts/backlog/run.sh <tag> nospec.yaml greedy,c1,c8,pf6` per run, so the server stamps every
dispatch of the passes it plays (`W device: RADIANCE_AQL_STAMP times every dispatch of one pass in 1 on card 0, into
…/<tag>.stamps.csv`), and `scripts/backlog/agg.py <tag>.stamps.csv <tag>.json --match 'mla_sink|merge_sink|qsa_work|
qsa_tail|idx_score|rope|row_front|kv_store|kv_project|kv_expand'` reads the rows of the kernels the item names.

Order: before-1, after-1, before-2, after-2, before-3, after-3, before-4 — interleaved, one card pair, the same command
line for each. A run is thrown away and repeated when its own server did not log `I server: listening on
http://127.0.0.1:8042` (another card's run may hold the port), when its `server.log` has an `E` line, or when its greedy
text is not the text every other run produced: **`k29-before-2` is such a run** — it was OOM-killed once, and its repeat
served a different model state (greedy text `83677d39…`, c1 21.6 ms/step, hit 0.95), so it is in the raw lines but in
none of the tables. `k29-before-4` is its clean replacement.

What moved and what did not:

- **The sink rows**, the item's main target, are 1.2–1.4 µs a launch faster (42 a step: 50 µs at c1, 59 µs at c8).
  `merge_sink`, the next launch on the same queue, is 0.3–0.9 µs a launch *slower*: it runs unchanged code and the
  stamp's exclusive time is `end − max(start, previous end on the queue)`, so the time the sink's prologue no longer
  spends in front of its wait is credited to the launch behind it. The group's union (sink rows + merge) is the number
  the step pays, and it is −3.9 % (c1) and −1.8 % (c8).
- **The row front** is −8.5 % at c8 (42 launches: 20 µs a step) and unchanged at c1, **`kv_expand_gate_quant`** −5.3 %
  at c8.
- `kv_expand_gate_quant` reads +4.3 % at c1 while the same kernel reads −5.3 % at c8 and the code it changed is one
  fewer instruction (a scalar flush the audit showed covered nothing); the spread of the unchanged rows is up to ±5 %
  run to run (`merge_sink` +3.6 % at c1 with unchanged code), so c1's kv_expand number is noise, not a cost.
- **`idx_score_kernel` and `rope_kernel` do not launch in the c1/c8 decode passes of this config** (`nospec.yaml`, 73-
  token prompts): they appear in the prefill-shaped pass kind of the greedy phase and in the long-context decode (below).

**0.6 µs a launch slower** (1.9 → 2.5 µs), the one row of the change that reads slower, and it reads the same way in the
greedy phase's prefill pass kind (1.89/1.91 → 2.62 µs a launch), so it is not a one-off: the plain rotary now works out
its three position components once per block into a small struct instead of at each use, which is one more value kept
live per thread in a kernel that is at the stamp's floor (1.9 µs). Its cost is 12 launches a step: 7 µs of a 15 ms
decode step, 0.03 %.

The pair's decode step is 14.795 → 14.817 ms (+0.15 %, inside the spread of the six runs above). The pair's *prefill*
phase is not comparable and not claimed: 17.3 s against 22.4 s (11.0 against 19.4 ms a prefill step), with the load
average 8 before the before run and 40 before the after run — three other runs were building and serving on the
machine (see the raw lines), and no part of this change is on the prefill's path.
