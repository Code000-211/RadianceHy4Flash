# P-11 arena multi-interval liveness — measurement

Issue: #81. Change: `rad_buf_full_write` (a plugin promises, per buffer, that each run of its
uses begins with a write that covers the buffer) and a planner that fits the runs instead of one
`[first use, last use]` envelope per buffer. What the item asks to see is the arena the plan
computes, and it is arithmetic: the same bytes on every run.

| | before | after | delta |

| arena, fixed region included (`arena_bytes`, the table row) | 1.40 GiB | 1.07 GiB | **−330 MiB a rank** |

attention scratch (`q_latent`, `k`, `v`, `attn_value`) whose runs now end before the same layer's
MoE scratch (`moe.shared_gate_up`, `moe.routed`, `moe.shared_out`) begins.

| 3 | `"wall": 3.353, "ttft": [0.069], "agg_tps": 76.355, "ms_step": 12.874` | not taken (lane lock held) |

The one after-run sits inside the before-run's own spread (12.874 – 12.897 ms a step, 76.219 –
76.355 tok/s), so this change is noise end to end, as a memory-layout change should be. Output
parity: the probe's prompt and generation are fixed by the lane (`prompt: [73]`, `gen: 256`,
`hit: 0.984`, `routed_per_step: 696.494`, `miss_units_per_step` 10.918 – 11.196 before and
10.9x after — the same routing), and no step was refused (the runtime's coverage guard would have
aborted the step by name; `server-exit=0`).
