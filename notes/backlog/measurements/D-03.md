# D-03: fused reduction twins for the draft layers (`ar_add_rmsnorm`), TP2 on the house rig

State: the change and both its card-less and served bars are here. The emulator case is byte-identical to the
chain it replaces on 36 geometries (either mode, every width and block count the row may be tuned to, plus the
refusals); the architecture tests cover the fused / undeclared / refused forms at one and two ranks and the TP2
split test now asserts the fused chain; and the served TP2 run below is byte-identical on all four greedy prompts
in six boots, with the draft pass 5 % cheaper in exclusive kernel time. The served decode rows are inside this
rig's noise, which the item's own estimate (0.3 % at c1, 0.7 % at c8) predicts.

## What the change is

- `libr4d/r4d_ar_add_rmsnorm.hip` (new): the exact two-rank all-reduce of a block's partial output with the
  residual add and the RMS norm beside it, one kernel, two orders — `mode` 0 is
  `all_reduce -> rmsnorm -> add` (the output projection's post-norm chain), `mode` 1 is
  `all_reduce -> add -> rmsnorm` (the MLP's sum and the norm that follows it). The fold is
  `r4d_ar_oneshot_2rank_exact`'s arithmetic (f32 sum of the two bf16 halves, rounded once through
  `bf16_hi_rne_nan`, stored back into `a` exactly as the standalone all-reduce stores it), the add is
  `add_bf16`'s word and the norm `rmsnorm_bf16`'s, in the same `kR4dSumLanes` partition and expression order, so
  the result is bit-identical at any width and block count. A block owns whole rows, so the block count clamps to
  M. Exact wire only. Built from the junction's AR device functions (`r4d_ar_seq.h`: handshake, push check,
  device-resident sequence, drain and acquire variants).
- `libr4d/r4d_rows.cpp`: the row (`cArAddRmsNorm` / `tArAddNorm` tuning axes: `nblocks`, `nthreads` 0/256/512/1024,
  `drain`, `acq`), its shape (`a`, `x`, `w`, `y`), its fuse decomposition (the three ops it replaces, for the
  oracle and for a library that refuses the launch) — and its **schema**, which the first lane boot found
  missing: the builder refuses an op no loaded plugin declares a schema for (`RAD_E_NOSCHEMA`) and the engine
  stopped at startup with `kernel 'ar_add_rmsnorm' in plugin 'libr4d' implements op 'ar_add_rmsnorm', which no
  loaded plugin declares a schema for` (the host twin's row names the same op, so both lines point at the one
  missing entry). The schema is `pAddRmsNorm`'s set plus the reduction's: `M` (the ranged parameter), `n`,
  `world_size`, `mode`, `eps`, `dtype`, with `wadd` / `mult` optional as the shim reads them. No card-less test
  sees this — the emu calls the entry point directly and the arch tests use the recording builder, which has no
  registry — so it is the served boot that reads the schema table.
- `arch/hyv4flash/hyv4flash_dfly.h`: both chains declare the twin where the layer has a post-norm, at two ranks,
  untapped, and the library declares the op; `op_post` / `op_add1` / `op_add2` / `op_final*` are cleared where it
  resolved, and `in_norm_done` skips the next layer's input norm (mode 1 writes it). Taps, `world != 2`, an
  undeclared op and a refused launch keep the old chain exactly as it was.
- Tests: `tests/r4d_emu/test_ar_add_rmsnorm.cpp` (both modes against the chain's own rows, byte for byte, at
  3-48 rows, n 1000-5128, widths 256-1024, one and several blocks, f32 and bf16 gains, plus the refusals);
  `tests/hyv4flash_arch_test.cpp` (`dfly2_takes_the_fused_reduction_add_norm_where_served_and_the_chain_otherwise`
  and the TP2 split test, which now reads `i_ar` from `L.op_ar_add` and `i_ar2` from `L.op_ar_next` and checks the
  twins' operands are the draft's own buffers).

## Findings

1. **Parity: exact.** Four greedy prompts, six boots, identical `sha256` and identical token counts — the served
   graph's bytes do not move, so the twins behave as the emu case says (the same arithmetic in the same order).
2. **The op is measurably cheaper in the served pass**: 19 fewer dispatches a draft pass, the families that carry
   the change down 29-32 % (c1) and 20-21 % (c8), the draft pass's exclusive sum down 3.2-3.5 % (c1) and
   5.1-5.2 % (c8). In ms: 0.13 ms of a 3.9 ms draft pass at c1, 0.25 ms of a 4.9 ms draft pass at c8.
3. **e2e: inside noise**, as the item predicts; no regression beyond it either (medians +0.8 % / +1.5 %, both
   arms' ranges overlap).
4. **The schema gap is the one thing the card-less tests cannot see.** The row, its axes, its shape, its fuse
   decomposition and the arch wiring were all in place and every test passed; the engine still refused to start
   on `RAD_E_NOSCHEMA`. A `RadOpSchema` entry is part of a new op, not documentation of it, and only a served
   boot or `radiance --check` against a real registry exercises it.

`<arm>-r<N>-stamp.csv`, `boot.log`, `probe.log`, `meta.txt`); not committed (110 MB a stamp file).
