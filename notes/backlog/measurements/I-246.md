Not a backlog item: issue #246, PR #247. Development tooling, so the merge bar is "nothing moves
without an override", plus the issue's Verify part: the override works on a card, and a reload of it
under a running server is taken, refused by name, and safe with requests in flight.

  before every run), u3 container, `nospec.yaml` as the lane renders it, 2026-11-25.
- Build: ROCm clang++, `-DRAD_WITH_HIP=ON -DRAD_GPU_TARGETS=gfx1201`, targets `radiance libr4d libavx
  hyv4flash` in each tree.

## 2. The override on a card

`cmake -DR4D_OVERRIDE_UNITS=r4d_gemm_iqr` + `ninja libr4d_override`: three build steps (the unit, the
override source, the link), 14.3 MB `override_home/kernels/libr4d.so`. The same unit built in a second tree
with `-DR4D_OVERRIDE_BASE=<the PR tree's libr4d.so>` compiled nothing else of libr4d (3 steps, 3 min 56 s
cold). At open: `serves 4 of the 644 rows of .../libr4d.so with its own hooks: gemm_iqr_nt_m64,
gemm_iqr_gated, gemm_iqr_dual, gemm_iqr_tiled`.

- `r4d_selftest --case` for the four rows, library alone and through the override
  (`RADIANCE_HOME=override_home:radiance_home`): every check passes in both, the same counts
  (nt_m64 1720, tiled 215, dual 17, gated 36 `ok`, 0 FAIL).
- The libref fallback of `r4d_selftest`: `--case idx_pool_gated_f32` through the override finds libref
  on `$RADIANCE_HOME` (6 `ok`, 0 ulp against libref, as the library alone); with the override's home
  alone it reports `skip ... libref's idx_pool_gated unavailable`, as before the change.
- `r4d_selftest --perfiqr 6144 2560 {1,64} 6`, two reps each, library / override: `iqr k6 m64` M=1
  24.1 / 24.1 us, `gemm_iqr_gated` 25.2 / 25.2 us, M=64 31.4-31.5 / 31.4 us.
- Served with the override loaded at start (two servers): greedy hashes as in §1, c1 72.20 / 72.28
  tok/s, c8 302.26 tok/s: the library's numbers.

  server whether or not a reload happened (the control row): that is the warm server (prefix cache, ttft

- The changed build's effect shows after its reload (+0.35-0.40 ms a decode step) and goes away with the
  next reload of the unchanged build.

- No `issued differently` / audit line in the server log after any reload (recorded passes dropped and

- Memory per reload (rebuilt copies stay mapped): host RSS +134-184 MB on the first reload, +6-49 MB on
  later ones; VRAM used +97-110 MB a card on the first reload, 0-13 MB on later ones.
