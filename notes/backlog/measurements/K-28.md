## Round 2: the tests the review asked for (no new numbers)

The code commit and the numbers above are unchanged; this round adds tests only, so the before / after of
`4ae1d77c` against `0fe700b7` still holds for the head.

- **The pass head's fallback outside `hc_enter`'s two to eight streams** (the blocking finding of round 1):
  `tests/hyv4flash_arch_test.cpp`, `a_pass_head_outside_hc_enters_range_copies_each_stream`. It declares a
  one-, a nine- and a sixteen-stream checkpoint (`hc_mult` 1, 9, 16): no `hc_enter` is declared, one wide
  `cast` of the embedding row into the streams with `n` = the row's width is, and a step issues that copy
  once a stream and no `hc_enter`. Past the last copy the replayed streams are hc copies of the embedding
  row. With the fallback dropped (the pass head declaring `hc_enter` at every stream count) the case
  fails at the first shape, `hc_enter`'s own declare refusing hc 1 and 9, which is what it is there to
  catch.
- **The selftest's narrow path through the alignment test alone** (judgement finding 2 of round 1):
  `libr4d/r4d_selftest.cpp` gives `Hy4Opd` a `skew`, bytes of poisoned red zone before the tensor, so a
  base is only two-byte aligned with the width and the pitch still multiples of eight; two geometries use it
  (the embedding row, the table). Run on iks, one `gfx1201` card, against the `libr4d.so` of this head:
  `gpu1 build/bin/r4d_selftest build/radiance_home/kernels/libr4d.so --case embed_lookup_bf16` — **8 cases,
  8 PASS, 0 FAIL**, the two skew cases byte for byte against libref, including
  `M 5 width 512, one entry a thread (x off 16-byte alignment)` and `... (wte off 16-byte alignment)`.
