## 1. Byte identity and the branch taken (`r4d_selftest --case moe_gemm_iqr`, one card)

The case compares each shape's `moe_gemm_iqr` output byte for byte against the dense IQR GEMM of the same
experts and rows, at both map settings the plugin pins (`r4d_moe_iqr_pin_map_tiles`: 4 = the 64-row run map,
8 = the packed 128-row map), and its new check reads the map back out of the scratch: a map entry is
`(expert | rows << 16)`, which `moe_iqr_packmap_kernel` fills from the runs' lengths and
`r4d_moe_blockmap_emit` leaves zero, so "some live entry carries a row count" says the packed map ran.

## 3. `R4D_PERF_IQR_GAP_MS=2`: attempted, not usable here

better) was run too, three interleaved pairs each way. It could not separate the arms on this machine: with the
other cards' builds on the host, single launches stalled for up to 4 ms inside a 2.2 ms measurement
(`2182.9..4025.2` a stretch), and the same arm's pin-8 phase came out 2.5 % *faster* than its pin-4 phase on the
