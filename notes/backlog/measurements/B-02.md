# B-02: `ngram-placement: ram=DIR` on a huge-page tmpfs (startup)

Measured by Gats-codeserk (outside worker, own host), posted on PR #243 / issue #108; committed here by the
reviewing maintainer without changing a number. Documentation and recipe change only: no engine code differs.

- before = merge base `a9d03cbef127fd5317480a75d0e295de93eb5330`; after = engine built at `a9d03cbe` as well (the
  variants differ only in `ngram-placement`, the PR's code commit `aa283e2` changes docs/README, not the engine).
- Machine: 2 x Radeon AI PRO R9700 (gfx1201), TP2, `power1_cap` read back 210 W, 247 GiB RAM, host Ubuntu 26.04,
  engine in `rocm/dev-ubuntu-24.04` (HIP 7.17.26434, AMD clang 24.0.0), `-DRAD_WITH_HIP=ON -DRAD_GPU_TARGETS=gfx1201`.
- Container `hy4-flash-iqr-v4-u3.rad`, 138093449672 B, sha256
  `c4a80918139f2bae4d097976fd2794ca3f1f56e9ea7eb60600188c45f4f5e7aa`.
- Config: the README TP2 recipe with `max-model-len: 65536`, `kernels: libr4d,libavx`, `host-pool-mib: 39000`.
- Method: seconds from engine start to `/health` answering (the engine's `startup: ready in` line agrees within 1.5 s),
  three interleaved rounds so the container page cache was warm for all variants.

## Rows (seconds to /health)

| Engram placement | fill | later starts (3) |
|---|---|---|
| `ram` | n/a | 31.1, 53.4, 36.0 |
| `ram=/dev/shm/radiance-ngram`, tmpfs default (`shmem_enabled=never`) | 58.9 | 35.8, 36.7, 36.6 |
| `ram=/dev/shm/radiance-ngram`, tmpfs `huge=always` | 32.1 | 22.2, 22.5, 22.5 |

Result: a reuse on a huge-page tmpfs saves about 13.5 s of a 36 s start; on a default tmpfs a reuse costs what `ram`
costs and the fill costs 23 s more.

## Parity

Greedy answer identical in all 15 starts (sha256 of the assistant message begins `efc192c6d1f9cfbe`); decode
68.8-69.5 tok/s for the same 64-token completion, measured on the second request. No change beyond noise.

## Not measured

Per-kernel Engram stamps (`RADIANCE_AQL_STAMP=1`) were not read; the gather reads 96-byte rows and the decode rate did not
move. `table_share_close` deletes the file when the last engine leaves cleanly (checked in `core/format/table_share.cpp`),
so the saving applies to a start after a crash or kill, not a planned restart.
