# B-04: container kept in the page cache (`--keep-container-cache`, opt-in)

Measured on the inference host (local lane, 2x R9700 gfx1201, 170 GB RAM, NVMe container 138.1 GB
`hy4-flash-iqr-v4-u3.rad`). Before = base `f2a0c7ef`, after = PR head merged with the base (`pr-173`).
Raw data: runs/local/ab-{base,pr}{1,2,3}/ (probe json), scratch logs of the start timings.

## 1. Off (default): no change

`nospec.yaml`, phases greedy,c1,c8, three interleaved runs per arm (base, pr, base, pr, ...), one lane.

| arm | c1 tok/s (3 runs) | c1 TTFT | c8 agg tok/s (3 runs) | c8 TTFT (first) |
|---|---|---|---|---|
| base | 74.67 / 74.26 / 74.55 | 0.096 / 0.099 / 0.094 | 322.0 / 318.5 / 323.0 | 0.069 / 0.086 / 0.068 |
| pr (off) | 74.67 / 74.52 / 74.51 | 0.093 / 0.094 / 0.093 | 323.0 / 321.7 / 321.2 | 0.069 / 0.069 / 0.079 |

Greedy output (3 prompts + a 5.7K arrival): the four sha256 are identical in all six runs
(d6da4fb3, 0699709c, e7a23c5d, f2987aea). With the flag off the code reduces to the old calls:
`dio_flags` is `RAD_DIO_READ | RAD_DIO_ALLOW_BUFFERED` as before, and `rad_drop_ranges(.., false)` is
`rad_keep_complement`.

## 2. On: the RAM check and the restart

The check runs after the load's pins (`lockable_room(container, 0, host margin)`: MemAvailable and
every memory cgroup). Container 128.61 GiB + 4 GiB headroom.

- Lane config (`nospec.yaml`, host pool 39000, ngram in RAM, ~104 GB pinned) with the flag on:
  "the container's pages are dropped behind the read: --keep-container-cache is on but 68.64 GiB of
  memory is available ... this wants 128.61 GiB with 4.00 GiB to spare". Server healthy, nothing held.
  This is the case of this host and of iks (112 GB): it never holds the cache next to the pinned pools.
- Config with room (host pool 30000, ngram `disk=`, prefix cache 2 GiB), time to /health, container
  evicted with fadvise before the cold start:

| start | flag off | flag on |
|---|---|---|
| cold (container not cached) | 28.1 s | 48.6 s (buffered read, slower) |
| restart 1 / 2 | 32.9 / 28.5 s | 17.1 / 16.8 s |

On: "the container stays in the page cache (128.61 GiB)". A restart is ~40 % faster (about 12-16 s) than
off; the first start costs ~20 s more. The gain is modest here because the NVMe reads 3.7 GB/s.
