# M-20 design: split gate_up / down placement + exact in-layer down prefetch, and "Weg 2" (resident experts first)

Design card of [M-20](../optimisation-backlog.md#m-20-asymmetric-gate_up--down-expert-placement--deterministic-in-layer-down-dma-prefetch-during-gate_up-moepic-style-vertical-split-arxiv250908342)
(issue #307). Every number below is measured on the **local lane** (2 x R9700, TP2, 210 W read back, u3 container,
`coupled03.yaml` = DFly2 and `nospec.yaml`, tree `d13d29c82`, built with the repeatable HIP compiler, CARDS.md §1.1);
the raw lines are in [measurements/M-20.md](../measurements/M-20.md) and the tools in
[measurements/M-20-tools/](../measurements/M-20-tools/). iks answered but was not needed: one lane per comparison.
At the owner's request the note also evaluates a second variant, **Weg 2** ("between experts", §5).

## 0. Verdict

- **M-20 as written (split placement + in-layer down prefetch): NO-GO.** Measured, it gains at one shape only
  (c8 DFly2: -2.9..-3.6 ms a 55 ms step at a gate_up share of 62-65 %), is neutral at c1 DFly2 (-0.2..-0.3 ms) and
  c8 no-spec (-0.4 ms), and **loses** at c1 no-spec (+0.07..+0.19 ms) and at long context as soon as the share
  reaches what the item proposes ("all gate_up resident": +0.7..+4.8 ms a pass at 63K / 4 x 60K). The item's two
  premises do not hold on the lane: a whole-unit miss costs 48-92 us of step, not "zero overlap / 66 us"
  in a fixed way, and the window (router end to down start) holds **0** down copies at c1 no-spec (44 us) and **1** at c1
  DFly2 (101 us), because a 0.58 MiB copy takes 57 us when both cards copy at once (§3).
- **Weg 2 without the split (exact in-layer whole-unit copies + resident experts run gate_up -> quant -> down first,
  the copied ones afterwards from VRAM): GO for verify / wide passes.** Modelled from the same measurements:
  c8 DFly2 **-5.0 ms a pass (~9 % of the step)**, c1 DFly2 -0.66 ms (2.6 %), c8 no-spec -0.46 ms (1.8 %), lctx4
  no-spec -1.4 ms; it needs no placement change, no split-ratio policy and no stager change. At c1 no-spec it is
  -0.21 ms before its fixed launch cost and about zero after it, and at long context with many misses a layer it must
  fall back to today's in-place reads (§4.3), so the build card scopes it to pass shapes the window can serve.
- **Owner's variant (§7, residency untouched, per miss: in place / early down copy / Weg 2, budgeted):** the early
  down copy competes with the miss's own in-place gate_up read (measured: the bytes do not add), so alone it pays only
  at DFly2 c8 (-2.7 ms) and no-spec lctx4 (-1.1 ms), and next to Weg 2 it is never chosen. **Build Weg 2 with a
  per-layer budget** (DFly2 c8 -5.0, no-spec lctx4 -2.9, DFly2 lctx4 -1.6, DFly2 c1 -0.7, no-spec c8 -0.6 ms a pass);
  the 8 x 32 GB RAM fix lowers today's miss stall ~15 % and halves small copy lists, independently.
- **M-20 + Weg 2 combined** adds nothing measurable over Weg 2 alone (c1 DFly2 -0.73 vs -0.66 ms, c8 DFly2 -4.9 vs -5.0
  ms, worse at long context). The split placement stays a parked option (§6 card W2-c), to be re-judged on traces
  once W2-b is in.

## 4. Expected gain per configuration and risks (question 4)

### 4.1 The model

Per routed layer (`evalm2.py`, scaled by live / simulated misses; 41 layers a pass):
- today: `(b_gu + b_dn) x n_full` (§3's slopes);
- M-20: full misses as today, `max(0, n_dn - k) x b_dn` for down copies that did not land (read in place), plus the plan
  and patch launches (2 x 2.6 us; 2.3-2.8 us is the measured exclusive time of the chain's smallest kernels);
- Weg 2: the resident experts' gate_up -> quant -> down run first, so the window becomes `W2 = W0 + T_down(no miss)`
  (+31 % at c8 DFly2, +50-60 % elsewhere); the missing whole units are copied meanwhile; then a tail
  gate_up/quant/down runs them from VRAM: `max(0, L0 + T_unit(n) - W2) + 12 us` (three tail launches + one expert);
- combined: split placement, and down-only and full misses both copied in the Weg 2 window.

### 4.3 Why the long-context rows go the other way

With 4-15 misses a layer the in-place reads of today's GEMMs overlap one another and cost 10-20 us a miss in the
fitted slope, less than the SDMA list's 33-57 us a down at TP2. Copying more than the window holds is a loss, and
spending gate_up's share of VRAM turns hot downs into misses. Both variants therefore need a per-layer cap: copy at
most `k_max(shape)` units (the list that lands inside the window, §3), read the rest in place in the tail, which is
today's cost for them. With the cap Weg 2 is never worse than today by more than its fixed launches.

### 4.4 Risks

- **Stager / prefill**: prefill rows (> 64) stay on today's path and the stager's own queue (first SDMA engine); the
  prefetch queue is the second engine. Both variants are off for staged steps; `lctxN-pre` passes (stage layers
  1,312 / 4,879-6,191) are untouched.
- **Plan kernel**: an extra launch costs ~2.6 us a layer (0.11 ms a pass); fold the mailbox write into
  `router_sigmoid_scatter` (it already holds `eoff`), so it costs nothing.
- **Tape**: today's `xp_predict` / `xp_mark` / `xp_step` are each a tape host step (`xprefetch.cpp:326-359`), three
  host breaks a layer in a recorded pass. The build must keep the recorded pass whole: the plan writes a per-pass
  sequence number that a device counter advances, the serving thread watches the mailbox continuously, and the patch /
  tail kernels read done words on the device. A tape break a layer is a no-go by itself.
- **CAS patching** (M-20) vs a heat-engine move: kept from xprefetch (an entry is redirected only where it still names
  the pool slot). Weg 2 needs no table patch: the tail kernels take the ring pointers as operands.
- **TP2 ordered dispatch**: no second compute stream, so no `engine_bringup.cpp:5362` penalty (+11 us an ordered
  start); the DMA list waits for no mark (its sources are static pool bytes; ring slots are reused three layers later
  behind the tail that read them). Both ranks route identically and copy their own halves; the slower card sets the
  all-reduce.
- **Uncached ring**: the tail GEMMs read `rad_dev_alloc_uncached` memory; whether `moe_iqr` / `moe_down_dec` lose
  bandwidth there is unmeasured: W2-a measures it with `rad-kbench`.
- **Memory**: a ring of `k_max` units x 3 layer groups: 16 x 3 x 1.43 MiB = 69 MiB a card (48 units, 0.23 points of
  residency).
- **Distinct from closed Z-08** (`refs/notes/tp2t3.md`): Z-08 predicted layer l+1 from layer l's router input
  (precision 23-46 %) on a second stream and paid 4-6 % for the machinery alone at TP2. Here the copies are the exact
  routed misses (precision 100 % by construction), posted after the router on the compute stream, and the window is
  inside the same layer.

## 5. Weg 2: resident experts first (the owner's questions)

**(a) The straggler tail.** Stamps of layers by their own miss count (p50, us), gate_up / down:

| misses in the layer | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| no-spec c1 | 34.4 / 22.1 | 74.7 / 54.3 | 135.5 / 97.6 | 191.3 / 145.8 | 270.5 / 199.6 |
| DFly2 c1 | 84.4 / 53.8 | 121.2 / 66.8 | 146.7 / 92.4 | 181.3 / 127.0 | 228.8 / 155.3 |
| no-spec c8 | 167.9 / 110.1 | 205.7 / 112.1 | 222.1 / 125.4 | 243.3 / 156.4 | 277.4 / 191.4 |
| no-spec lctx4 | 94.1 / 61.3 | 118.7 / 67.0 | 148.2 / 100.8 | 192.1 / 136.7 | 242.2 / 169.5 |

So one miss makes 54 % of a c1 no-spec gate_up launch tail (34 -> 75 us), 30 % at c1 DFly2, 18 % at c8 no-spec; at
DFly2 c8 the headroom slope gives 22 us gate_up + 32 us down a miss on ~3 misses a layer, 13 % of gate_up and ~40 % of
down. In that tail every resident expert's down waits.

**(b) Launch count.** Splitting costs three launches (tail gate_up, quant, down) a layer with misses, measured at
2.3-2.8 us each in the chain (~8 us a layer, 0.32 ms a pass if every layer carried them). Avoiding it: (1) only pass
shapes whose window serves the copies get the split form (a recorded pass is per shape: verify passes and c >= 4
decode); (2) the tail kernels take `eoff` ranges and a "missing" bitmask from the plan and exit at once when the layer
has no miss (a launch still costs its ~2.6 us, so (1) matters more); (3) one launch ordering resident blocks first
(K-55's idea) does not open the window, because the down of the resident set cannot start before that launch ends;
(4) the chained form (`r4dchain`) keeps the tail in the chain, so no stream wait and no tape break.

**(c) Bit identity.** Splitting the experts of one launch over two launches changes no summation: `moe_iqr` reduces a
tile over its K waves inside one block (`r4d_moe_iqr.hip:513-541`), `moe_down_dec` accumulates a tile over all of K in
order and writes each `edn` row once (`r4d_moe.hip:1855-1866`), the quantiser works per row, the routing sort
(`eoff`, `sorted`) is unchanged and the gather combines `edn` rows by their sorted index afterwards. Conditions the
build must keep: the tail runs the same template instance and tile geometry per expert as the full launch (the
geometry choice depends on the pass's rows, so pass the same `M`); not with the packed prefill map
(`moe_iqr_packmap`, which may tile across experts; Weg 2 is decode / verify only); the protected experts' `op_pgu`
stays ordered after the tail (it writes the zeroed rows behind the down). Greedy sha256 identity is the merge bar.

**(d) Combined, and order.** §4.2: Weg 2 alone takes almost all of the gain; adding the split adds -0.07 ms at c1
DFly2 and costs elsewhere. Gain per effort: W2-a (exact in-layer copy engine at TP2, no consumer: M) -> W2-b (resident
first + tail, verify / c >= 4 shapes: M) -> only then re-judge the split (W2-c) on fresh traces.

**K-55** ("non-resident experts first", closed as small) reordered blocks *inside one launch* so the in-place link
reads start at t = 0, for prefill; it hides at most the launch's own compute and moves nothing off the link. Weg 2
moves the bytes to the SDMA engine before they are needed, so the link runs under quant and the resident down as well,
and the missing experts' GEMMs read VRAM.

## 6. Build cards (question 5)

**W2-a: exact in-layer copy engine at TP2 (switch `RADIANCE_XP_EXACT`, default off).** Plan in
`router_sigmoid_scatter` (writes the layer's missing units into the mailbox, capped at `k_max` per shape); serving
thread posts `rad_xp_list` without a mark; ring of 16 units x 3 groups; per-pass sequence on the device (no tape
host steps); `/stats` `xp_exact` posted / landed-before-down / dropped. No consumer yet. Merge bar: ctest `place_*`,

noise of off (the machinery's cost, the thing that killed Z-08) and the landed-before-down share at c8 DFly2 >= 90 %;
`rad-kbench` `moe_iqr` / `moe_down_dec` reading the uncached ring vs normal VRAM.

**W2-b: resident first + tail from the ring (verify passes and c >= 4).** The routed block issues gate_up -> quant
-> down over the resident experts, then the tail over the missing ones, reading ring pointers where landed and the pool
in place otherwise. Merge bar: greedy sha256 byte-identical (CARDS.md §2.1) on both configs; `RADIANCE_AQL_STAMP`
routed-block time a layer down at c8 DFly2 (target -3 ms a pass or better) with no ordered-dispatch regression;
served `coupled03.yaml` c1/c4/c8 and `nospec.yaml` c1/c8/lctx4 A/B, 3 interleaved runs, c1 not worse beyond noise.

**W2-c (parked): split placement.** `build_units` by `(layer, expert, slot)` and two slab classes, gate_up share
bounded to 62-65 % and lowered at long context. Opened only if W2-b's measured residual stall at c8 DFly2 is above
1 ms a pass and a fresh trace simulation (this note's `rtrace.py` + `evalm2.py`) shows >= 1 ms more.

## 7. Variant: residency untouched, per-miss path choice (in place / early down copy / Weg 2)

The owner's variant keeps whole-unit residency as it is and only changes how a layer's **misses** are served. Per
layer and per miss the plan picks:
1. **in place** (today): `moe_iqr` reads gate_up and `moe_down` reads down over PCIe;
2. **early down copy**: gate_up still read in place, the 0.58 MiB down copied by SDMA right after the router into a
   small VRAM ring, so it lands while gate_up of all experts + the activation quantiser run; `moe_down` reads it from
   VRAM (the same bytes, so bit-identical);
3. **early whole-unit copy + run it last** (Weg 2, §5) for that expert;

under a per-layer budget so the copies fit their window; everything beyond stays on path (1).

### 7.1 One extra measurement: the in-place read and the SDMA copy on the same card

The note's earlier model treated the down copy as free inside the window. It is not: the miss expert's in-place
gate_up read and its down copy pull from the same link and the same DRAM channels. `M-20-tools/ccbench.cpp`
measures exactly this: a read kernel with the decode `moe_iqr` grid of one expert (96 blocks x 128 threads) reads n x
891,136 B from pinned THP host memory while `hipMemcpyAsync` (SDMA) copies k x 608,768 B, on one card and on both
cards at once. Run under `flock /tmp/radiance-lanes/gpu.lock gpu2` (cards 0,1, cap 210 W read back, no server),
150 reps, p50; **host load 0.30-0.44 (quiet)**, 2 s on the GPUs. Both cards at once (per card; card 1 within 3 %):

| n gate_up reads / k down copies | read alone | copy alone | read with copy | copy with read | sum alone -> together |
|---|---|---|---|---|---|
| 1 / 1 | 60.8 us | 54.9 | 101.1 (+40) | 99.6 | 116 -> 101 |
| 2 / 2 | 95.3 | 81.6 | 127.8 (+33) | 157.7 | 177 -> 158 |
| 3 / 1 | 131.7 | 54.7 | 157.7 (+26) | 150.4 | 186 -> 158 |
| 3 / 3 | 132.6 | 119.6 | 167.2 (+35) | 242.0 | 252 -> 242 |
| 8 / 8 | 332.1 | 305.7 | 401.8 (+70) | 607.3 | 638 -> 607 |
| one card, 1 / 1 | 49.5 | 37.2 | 71.3 (+22) | 71.8 | 87 -> 72 |
| one card, 3 / 3 | 120.4 | 119.6 | 133.7 (+13) | 189.0 | 240 -> 189 |

**The bytes do not add.** With both flows running, a card moves only 6-18 % more than the faster flow alone (one card
10-38 %); the read kernel keeps ~80 % of its rate (60 % at 1/1), the copy gets 25-40 %. So an early down copy
**slows the gate_up of the misses it belongs to**, by 26-40 us at small n, and the copy itself takes about twice its
standalone time while the in-place reads run. The in-place read is latency-bound, not link-bound: with no DRAM
contention (one card) it gets only 15-20 % faster (60.8 -> 49.5 us), while a lone 0.58 MiB SDMA copy gets 2x faster
(57.2 -> 25.7 us, `rad_xp_list`).

### 7.2 The model

`M-20-tools/var.py` (inputs: the live-miss histograms per layer of `rtrace.py --out` for both configs; the per-shape
fits of §3: `T_gu0, b_gu, T_dn0, b_dn, W0`; own-phase fits for lctx). Per routed layer with n live misses and a
choice of a whole-unit copies, b early downs, c = n-a-b in place:
- the SDMA list (b downs first, then a units) starts `L0` = 10 us after the router end (host handover; 0 with a
  device doorbell); its standalone time is the measured `rad_xp_list` table (both cards today; one card = the
  fixed-RAM proxy, which is what the different-region pairs of pcie-h2d show: 23-28 GB/s a card at once);
- it shares the link with the in-place gate_up reads of the b+c experts as measured in §7.1 (fluid: read 0.6 /
  copy 0.57 of their rates while both run at n = 1, 0.8 / 0.28 from n = 2; fixed RAM 0.69/0.52, 0.83/0.30); the
  gate_up kernel is delayed by the read's stretch times the exposed share of that read today
  (`e = b_gu x n / read time`, 0.44-0.92);
- `down start = W0 + b_gu x (b+c) + delay`; an early down saves `b_dn` only if it landed by then (otherwise
  `moe_down` reads it in place: the plan writes a redirect that the SDMA list itself sets after the copy, so a late
  copy falls back automatically); in-place downs still running beside the list pay their share too;
- whole units run in a tail after the resident down: `max(down end, list end) + 4.2 us`; the tail's three launches
  (7.8 us) and the plan launch (2.6 us) are charged on **every** layer of a pass where the shape enables them (a
  recorded pass launches the same kernels whether a layer has misses or not);
- per layer the plan takes the best (a, b) for its n (that is the budget: k_max(n, shape)); a pass shape keeps the
  variant only if its total is negative ("never worse than today except the plan kernel");
- fixed RAM (8 x 32 GB, ~23-25 GB/s a card at once): copy tables of one card, in-place stall per miss x 0.85
  (the one-card / two-card ratio of the read kernel).

### 7.4 What wins where

- **(2) alone does not pay its way except at DFly2 c8 (-2.7 ms) and long-context no-spec (-1.1 ms).** At c1 / c8
  no-spec and DFly2 c1 the down copy costs the miss's gate_up about as much (26-40 us, §7.1) as it saves in
  `moe_down` (`b_dn` 13-36 us), and the plan launch eats the rest. It needs a large `b_dn` (31.5 us at DFly2 c8) and
  a window wide enough that the copy lands while the in-place reads are not on the link (DFly2 c8: 473 us).
- **(2)+(3) budgeted = Weg 2 budgeted.** Given the choice, the plan almost never takes (2) when (3) is on the menu:
  the whole-unit copy removes the in-place gate_up read as well (so there is nothing for the copy to fight over the
  link) and has the longer window (`W0 + T_dn0`). The difference is 0.00-0.02 ms in every row. **Adding (2) to Weg 2
  is not worth its plan/redirect machinery.**
- **The budget is what matters**, not the third option: "every miss copied" loses at long context (+3.4 / +4.0 ms
  DFly2 lctx1 / lctx4, +1.0 ms no-spec lctx1) and is 0.2-1.3 ms worse at c8 / lctx4; the per-layer cap from the miss count fixes
  that (lctx rows go from loss to -1.6 / -2.9 ms or "off").
- **Weg 2 budgeted** is the variant to build (as §6 W2-a / W2-b, now with the per-n cap): DFly2 c8 -5.0 ms, DFly2
  lctx4 -1.6, no-spec lctx4 -2.9, DFly2 c1 -0.7, no-spec c8 -0.6; off at no-spec c1 and lctx1 unless the launch costs
  go (folded plan + tail launched only with misses: then -0.3 / -0.0).
- **RAM fix (8 x 32 GB):** cuts today's stall only 15 % (the in-place read is latency-bound), but halves a small copy
  list. It makes (2) slightly positive at DFly2 c1 (-0.27) and helps the long-context rows (-0.3 to -0.5 ms more), and
  leaves a little less to win at c8 because the baseline is faster. Combined with Weg 2: DFly2 c8 6.46 -> 1.4 ms of
  miss stall a pass (today RAM, Weg 2) or 5.49 -> 1.1 (fixed RAM); the RAM fix and Weg 2 do not add up, they attack
  the same stall.
- **Device doorbell:** 0.00-0.09 ms. Not worth it for this alone; the window is limited by link sharing, not by the
  10 us handover.

### 7.5 Risks

- **Proxy, not `moe_iqr`.** §7.1 uses a pure read kernel with the decode grid of one expert; the real kernel computes
  between reads, so it may compete less (better for (2)). The exposure factor `e` and the fluid shares are fitted on
  the proxy. Worst case (e = 1) changes only (2) materially (DFly2 c8 -2.7 -> -2.0). An A/B of (2) on the engine is
  the only real check; Weg 2's numbers barely depend on it (in its best plan no read runs beside the list).
- **Fixed RAM is modelled by one card alone today** (no DRAM contention between the cards); pcie-h2d's different-
  region pairs support that, but a re-measure after the swap is owed, and CPU-side memory traffic (Engram gather,
  CPU MoE parts) still shares the budget.
- **Launch cost in a recorded pass.** The base rows charge the plan (2.6 us) and the tail (7.8 us) on every layer;
  whether the chained form can skip empty tails decides no-spec c1 / lctx1 (sensitivity row 2). Folding the plan
  into the router kernel is cheap and worth doing first.
- **Copy start-up under TP2** (57 us for one 0.58 MiB down on both cards, ~24 us of it start-up) dominates small
  lists; the ring/doorbell design must not add host work in the recorded pass (§4.4 tape risk stands).
- **Late copies.** With the SDMA list writing the redirect after the bytes, a late copy falls back to the in-place
  read automatically, but it then competes with that read: a mispredicted budget costs up to one copy time
  (~57 us) in that layer. The cap must come from the measured k_max(n, shape), conservatively.
- **Uncached ring reads** by `moe_down_dec` / the tail `moe_iqr` are still unmeasured (W2-a's `rad-kbench` item).
- **Bit identity:** (2) reads identical bytes from another address (no change); (3) is §5(c).
- Sources of the inputs: the run directories are gone; the per-phase fits are §3 / measurements §3, the miss
  histograms come from the `rtrace.py --out` JSONs that were still in the M-20 scratchpad (`sim-c03-2-d0.8.json`,
  `sim-nospec-2-d0.8.json`, `live` histograms, so no live/simulated scaling).

**Verdict for the variant:** build **Weg 2 with a per-layer, per-miss-count budget** (W2-a + W2-b); skip option (2)
(alone it helps one shape, combined it adds nothing); swap the RAM independently (it lowers every baseline, ~15 % of
today's miss stall, and makes the copy lists twice as fast at small n).
